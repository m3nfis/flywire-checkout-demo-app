API guide

Call the API from your backend

Use these compact backend examples to create, resume, and inspect sessions, then connect them to related payment operations such as token charge, capture, and preauthorization extension.

View reference Understand events

Integration flow

  1. 1Create session
    Call the Flywire Checkout V2 public API from your backend.
  2. 2Pass run values
    Send only the session run identifiers and token to the browser.
  3. 3Query or process events
    Use backend follow-up for operational state.
Backend only:

Call these endpoints from your server with YOUR_PUBLIC_API_KEY. Do not expose public API credentials in browser code.

Create, resume, and inspect sessions

Create a session

Create an authenticated session shortly before checkout starts. The response gives your backend the session id, session run id, and session run token to pass to the frontend.

POST YOUR_PUBLIC_API_BASE_URL/commercial-payex/v2/session
X-Authentication-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

{
  "config": {}
}
{
  "id": "SESSION_ID",
  "run_id": "SESSION_RUN_ID",
  "run_token": "SESSION_RUN_TOKEN"
}

Your production request should also include the required recipient, payer, transaction, and checkout configuration fields for your integration.

Backend notifications

Create a session with eventUrl

Add config.eventUrl when your backend should receive selected server event notifications for the session. If it is omitted or empty, no client server event notifications are sent.

POST YOUR_PUBLIC_API_BASE_URL/commercial-payex/v2/session
X-Authentication-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

{
  "config": {
    "eventUrl": "https://example.com/cpx-events"
  }
}

See the events guide for delivery handling and HMAC digest verification.

Continue checkout

Resume a session

Resume an existing session when the payer is returning to an unfinished transaction or when a previous session run expired. Return the fresh run values to your frontend.

POST YOUR_PUBLIC_API_BASE_URL/commercial-payex/v2/session/SESSION_ID
X-Authentication-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

{}
{
  "id": "SESSION_ID",
  "run_id": "SESSION_RUN_ID",
  "run_token": "SESSION_RUN_TOKEN"
}
Backend follow-up

Get session info

Use session lookup when your backend needs current status after on_end, after an event notification, or during operational reconciliation.

GET YOUR_PUBLIC_API_BASE_URL/commercial-payex/v2/session/SESSION_ID
X-Authentication-Key: YOUR_PUBLIC_API_KEY

The response contains the latest session information available to your integration. Keep business decisions on your backend rather than relying only on browser callbacks.

Related Payments API operations

Payment operations

Some integrations also use Payments API operations after checkout, especially when charging a saved token or managing a preauthorized payment. Keep these calls on your backend and use the formal API reference for complete schemas.

Charge token

Charge a previously created payment method token. This abbreviated body shows the main fields; include the recipient and item details required by your integration.

POST YOUR_PUBLIC_API_BASE_URL/payments/v1/payments/charge
X-Authentication-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

{
  "payment_method_token": "TOKEN_ID",
  "mandate_id": "MANDATE_ID",
  "payor_id": "PAYOR_ID",
  "recipient": {},
  "items": [
    {
      "amount": 12345
    }
  ],
  "charge_intent": {
    "mode": "unscheduled"
  }
}

Capture payment

Capture funds for a payment that was authorized but not captured immediately. The schema is abbreviated; include the amount you want to capture.

POST YOUR_PUBLIC_API_BASE_URL/payments/v1/payments/PAYMENT_ID/captures
X-Authentication-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

{
  "amount": 1200
}

Extend preauth

Extend the authorization window for an active preauthorized payment. Include an amount when adjusting the authorized amount as part of the operation.

POST YOUR_PUBLIC_API_BASE_URL/payments/v1/payments/PAYMENT_ID/authorization_adjustments
X-Authentication-Key: YOUR_PUBLIC_API_KEY
Content-Type: application/json

{
  "amount": 15000
}
Client-safe examples

Placeholder conventions

Examples on this page intentionally use placeholders instead of environment-specific values or real identifiers.

  • YOUR_PUBLIC_API_BASE_URL for the public API host used by your backend.
  • YOUR_PUBLIC_API_KEY for the API credential stored on your backend.
  • SESSION_ID, SESSION_RUN_ID, and SESSION_RUN_TOKEN for session values returned by the Flywire Checkout V2 session API.
  • PAYMENT_ID, TOKEN_ID, MANDATE_ID, and PAYOR_ID for related payment operations.
  • https://example.com/cpx-events for a client-owned event receiver URL.
