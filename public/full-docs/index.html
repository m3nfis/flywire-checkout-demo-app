Client documentation

Add secure checkout with Flywire Checkout V2

Flywire Checkout V2 helps client teams launch payment and tokenization checkout flows with a hosted runtime, backend-controlled sessions, and clear follow-up through session status and events.

Start integrating Understand sessions

Recommended path

  1. 1Create a session
    Your backend creates or resumes a Flywire Checkout V2 session.
  2. 2Start checkout
    Your web app loads connect.js and calls window.cpxCore.start.
  3. 3Confirm outcome
    Your backend uses events or session status for final follow-up.
Production recommendation:

Use authenticated sessions when you can. Anonymous sessions are available for lightweight frontend-only setups, but they provide less control and are not the recommended production path.

Capability summary

What you can build

Flywire Checkout V2 provides a browser checkout experience for collecting payments, creating tokens for future use, and guiding payers through available payment options. Your team keeps sensitive setup and operational decisions on the backend while the hosted runtime manages the checkout UI.

Payment checkout

Start a payment flow with amount, recipient, payer, and session context supplied by your integration.

Tokenization flows

Use tokenization, optional tokenization, or implicit tokenization depending on how you want to save payment details.

Embedded experiences

Open checkout as the default hosted experience or embed it into a container in your page when your UX requires it.

4-step integration

Recommended integration path

  1. Create or resume a Flywire Checkout V2 session from your backend through the public API.
  2. Return only the safe browser values to your frontend: SESSION_ID, SESSION_RUN_ID, and SESSION_RUN_TOKEN.
  3. Load connect.js from the appropriate environment and call window.cpxCore.start(cpxInitFields) with recipient, transaction, response, and session fields.
  4. Use onEnd and onError to update the browser experience, then let your backend query session status or process configured events for payment follow-up.

For the full copy-paste sequence, continue with the integration guide. For session lifecycle details, see sessions.

System roles

How the pieces work together

Client browser

Loads the connector from the gateway and starts checkout with the session values supplied by your backend.

Client backend

Creates or resumes sessions, keeps API credentials out of the browser, and performs final status checks.

Flywire Checkout API

Creates session runs, returns browser-safe run values, and exposes session status for follow-up.

Checkout runtime

Presents the payment or tokenization UI and reports browser completion or cancellation through callbacks.

Events

Sends backend notifications to your configured eventUrl, such as https://example.com/cpx-events.

Status checks

Let your backend retrieve the latest session state when the browser returns from checkout or when your operations need confirmation.

onEnd tells your frontend that the checkout UI completed or was canceled. Treat it as a user-experience signal, not the only source of payment truth. Session status, events, and API responses are the backend sources for follow-up.
