Reference

Initialization field reference

Use this concise reference when constructing the cpxInitFields object passed to window.cpxCore.start(cpxInitFields).

Start integrating Review capabilities

Required shape

  1. 1recipient
    Identifies the client and recipient code.
  2. 2transaction
    Selects payment, tokenization, or combined behavior.
  3. 3response
    Handles checkout completion and errors in the browser.
Runtime entry point:

After loading connect.js from the correct environment (https://checkout.demo.flywire.com/gateway/connect.js for demo, https://checkout.flywire.com/gateway/connect.js for production), start checkout with window.cpxCore.start(cpxInitFields).

Minimum browser call

Quick start shape

The browser startup object usually contains recipient, transaction, session, and response fields. Authenticated sessions are recommended for production integrations.

window.cpxCore.start({
  recipient: {
    clientId: "YOUR_CLIENT_ID",
    code: "YOUR_RECIPIENT_CODE"
  },
  transaction: {
    type: "payment",
    details: {
      amount: "123.45"
    }
  },
  session: {
    id: "SESSION_ID",
    runId: "SESSION_RUN_ID",
    runToken: "SESSION_RUN_TOKEN"
  },
  response: {
    onEnd: function (reason, payload) {
      console.log("Checkout ended:", reason, payload);
    },
    onError: function (type, payload) {
      console.error("Checkout error:", type, payload);
    }
  }
});
Required recipient context

recipient

recipient tells Flywire Checkout which client and recipient configuration should be used for checkout.

clientId

Required string. Use the client identifier provided for your integration.

code

Required string. Identifies the recipient receiving the payment or tokenization context.

fields

Optional key-value bag for recipient-specific values. Values may be strings or booleans.

recipient: {
  clientId: "YOUR_CLIENT_ID",
  code: "YOUR_RECIPIENT_CODE",
  fields: {
    accountReference: "YOUR_ACCOUNT_REFERENCE"
  }
}
Payment behavior

transaction

transaction selects the checkout mode. Amount values are strings in the frontend init fields.

payment

{ type: "payment", details: { amount } }. Use for standard payment collection.

tokenization

{ type: "tokenization" }. Optional details can include amount and preauthorization.

optionalTokenization

{ type: "optionalTokenization", details: { amount } }. Collect payment and offer token storage where supported.

implicitTokenization

{ type: "implicitTokenization", details: { amount } }. Collect payment while creating a reusable method where supported.

authorization

Optional "preauth" value inside details for supported preauthorization flows.

details.amount

Required for payment, optional tokenization, and implicit tokenization. Optional for tokenization when details are present.

Authenticated checkout

session

session connects the browser checkout startup to a backend-created or backend-resumed Flywire Checkout session run. Pass only the browser-safe values returned by your backend.

  • id: the session identifier, shown in examples as SESSION_ID.
  • runId: the session run identifier, shown as SESSION_RUN_ID.
  • runToken: the session run token, shown as SESSION_RUN_TOKEN.

See sessions for lifecycle guidance and the API guide for backend examples.

Optional payer prefill

payer

payer.fields can prefill payer details and reduce manual entry. Supported fields include firstName, middleName, lastName, email, phone, address, city, state, zip, and country.

payer: {
  fields: {
    firstName: "PAYER_FIRST_NAME",
    lastName: "PAYER_LAST_NAME",
    email: "payer@example.com",
    phone: "PAYER_PHONE",
    country: "US"
  }
}
Runtime options

config

config controls optional runtime behavior. Only set fields that are part of your approved integration design.

env

Optional environment selector. Use the value provided by Flywire for your integration.

locale

Optional locale. Supported values are en, en-US, es, es-ES, fr, fr-FR, de, de-DE, pt, pt-PT, it, it-IT, ko, ko-KR, zh, zh-CN, ja, ja-JP, id, id-ID, vi, and vi-VN.

embedTo

Optional CSS selector for embedded checkout, for example #cpx-checkout.

offerRules

Optional filters and sort order for checkout offers by method, currency relationship, and supported advanced filters.

Form controls

showPayerForm, showRecipientForm, and disabledFields control form display and locked fields.

Additional options

l2l3, skipMQC, and disablePayerEmails are optional integration-specific settings.

Frontend callbacks

response

response.onEnd is required and runs when checkout ends in the browser. The reason can be completed or canceled. The payload may include session status and a paymentReport with payment status, amount, currency, and watchlist values.

response.onError is optional and can receive categories such as payment, initFields, sessionRunStart, offers, captcha, smartSession, and sessionRunEnd.

Do not rely only on callbacks:

Use onEnd for browser messaging and navigation. Use backend session lookup and/or events before making final payment, order, or fulfillment decisions.

Offer filtering

window.cpxCore.start({
  recipient: {
    clientId: "YOUR_CLIENT_ID",
    code: "YOUR_RECIPIENT_CODE"
  },
  transaction: {
    type: "payment",
    details: {
      amount: "123.45"
    }
  },
  session: {
    id: "SESSION_ID",
    runId: "SESSION_RUN_ID",
    runToken: "SESSION_RUN_TOKEN"
  },
  config: {
    offerRules: {
      filters: {
        method: ["credit_card", "bank_transfer"],
        currency: ["payerCurrency", "recipientCurrency"],
        advanced: ["isNotAmex"]
      },
      sort: [
        {
          field: "currency",
          order: ["payerCurrency", "recipientCurrency"]
        }
      ]
    }
  },
  response: {
    onEnd: function (reason, payload) {
      console.log("Checkout ended:", reason, payload);
    },
    onError: function (type, payload) {
      console.error("Checkout error:", type, payload);
    }
  }
});

Callbacks

function startCheckout(session) {
  window.cpxCore.start({
    recipient: {
      clientId: "YOUR_CLIENT_ID",
      code: "YOUR_RECIPIENT_CODE"
    },
    transaction: {
      type: "payment",
      details: {
        amount: "123.45"
      }
    },
    session: {
      id: session.id,
      runId: session.runId,
      runToken: session.runToken
    },
    response: {
      onEnd: async function (reason, payload) {
        console.log("Checkout ended:", reason, payload);
        await fetch(`/your-backend/cpx-sessions/${session.id}/status`);
      },
      onError: function (type, payload) {
        console.error("Checkout error:", type, payload);
      }
    }
  });
}
